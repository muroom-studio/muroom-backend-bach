# 지원금은 전부 마케팅에 썼습니다. 그래서 AWS는 사비로 돌렸습니다

*직접 창업한 5인 스타트업 Muroom을 만들고 접기까지 10개월의 회고, 3부작 중 1부. 모든 수치는 실제 AWS 청구서와 git 히스토리에서 가져왔습니다.*

---

작년에 5인 팀(디자이너 둘, 프론트 하나, 백엔드는 저와 팀원 둘)으로 Muroom을 창업했습니다. 서울의 합주실·연습실을 지도로 찾는 서비스였고, Spring Boot 모놀리스 하나, PostGIS 얹은 PostgreSQL 하나, 그리고 콜드콜로 직접 확보한 사장님 110명과 스튜디오 130개·룸 1,273개의 데이터가 전부였습니다.

학교 창업 지원금에는 함정이 하나 있었습니다. 우리가 그걸 전부 마케팅 예산으로 배정해 버렸거든요. 서버비는 사비였습니다. 이 제약 하나가 이후 제가 내린 거의 모든 인프라 결정을 좌우했고, 어떤 튜토리얼보다 많은 걸 가르쳐 줬습니다.

나중에 스타트업 프로그램에서 $1,000 크레딧을 받긴 했습니다. 하지만 그 전까지, 모든 아키텍처 선택의 KPI는 하나였습니다. 제 통장 잔고요.

## "비용 최적화"의 실체

인프라는 처음부터 끝까지 제가 맡았습니다. 처음엔 콘솔에서 손으로 클릭했고, 2월에 Terraform으로 이관했습니다. 최종 아키텍처는 prod와 dev **두 환경을 월 $150 정도**로 돌렸는데, 그 돈이 사주지 않은 것들은 이렇습니다:

- **NAT 게이트웨이 대신 NAT 인스턴스.** nftables 마스커레이드를 돌리는 `t4g.nano`는 월 $3 남짓, 관리형 NAT 게이트웨이는 데이터 처리비 빼고도 $32부터 시작합니다. 대신 단일 장애점이 생깁니다. 그래서 제가 허용한 알람 4개 중 2개가 이 NAT 몫입니다.
- **RDS 대신 EC2 자체 운영 PostgreSQL.** 사실 처음엔 RDS였습니다. 사비 부담이 조여 오자 `t4g.small`로 옮기고 PostGIS를 user-data에서 직접 빌드했습니다. 첫 시도는 유명한 커뮤니티 PostGIS 이미지였는데 세 가지 방식으로 실패했고, 리포에 남은 "공식 이미지에서 직접 빌드"라는 그럴듯한 구성은 사실 그 실패의 산물입니다.
- **ElastiCache 대신 EC2 위의 Valkey.** ACL 인증, AOF 영속화.
- **prod와 dev가 VPC 하나, ALB 하나를 공유.** 호스트 헤더로 라우팅하고, 기본 액션은 404 고정 응답이라, IP만 두드려서는 아무것도 알 수 없습니다.
- **외부 API 키 12개를 환경당 시크릿 1개에 몰아넣기.** Secrets Manager는 시크릿 개수로 과금하니까요. 제 Terraform 주석에는 아직도 "비용 절감 차원"이라고 적혀 있습니다.

## 관리형을 버리되, 보증은 버리지 않기

RDS를 버린다는 건 자동 백업, 페일오버, 자격증명 로테이션을 버린다는 뜻입니다. 중요한 것들은 직접 되찾으려 했습니다:

- **백업 3중화.** DLM으로 매일 EBS 스냅샷, 매일 밤 `pg_dump`를 S3(Intelligent-Tiering)로, 그리고 systemd 루프가 **10초마다 WAL 세그먼트를 S3로 쉬핑**. 가난한 자의 PITR입니다.
- **AWS가 관리하지 않는 DB에 자동 로테이션 달기.** RDS용으로 만들어진 표준 SAR 로테이션 Lambda를 자체 호스팅 Postgres에 붙였습니다. 어차피 libpq로 말하니까 동작합니다. 앱 쪽은 AWS Advanced JDBC Wrapper의 `awsSecretsManager` 플러그인이 인증 실패 시 자격증명을 다시 가져오므로, 로테이션에 재배포가 필요 없습니다. dev는 매일(카나리), prod는 매주. 이걸 붙이는 데 하룻저녁과 커밋 4개가 들었고, 마지막 커밋 제목은 *"fix … 3차!!!!!!!!!!!!!!!"* 입니다. "간단한 연동"이라는 말의 실체를 기리는 기념비로 히스토리에 남겨 뒀습니다.
- **SSH 전면 금지.** 모든 인스턴스는 SSM Session Manager로만 접근합니다. 계정에 키페어가 하나도 없습니다.

## 비용 압박이 제품까지 도달했을 때

가장 선명한 교훈은 인프라 바깥에 있었습니다. 검색 결과에는 원래 가장 가까운 지하철역까지의 *도보 시간*이 표시됐는데, 유료 길찾기 API를 스튜디오마다, 페이지마다 호출하는 구조였습니다. 사용자가 지도를 움직일수록 비용이 정비례로 늘었죠.

무료 대안도 우리를 구해주지 못했습니다. 지오코딩은 이미 정부의 도로명주소 API를 쓰고 있었는데, 무료이기도 했지만 민간 지도 API는 결과를 우리 DB에 저장하는 것 자체가 약관 위반이었기 때문입니다. 저장해도 되는지 **기관에 직접 전화해서 확인**까지 했습니다(된답니다). 하지만 공공 API에는 엄격한 쿼터가 따라옵니다. 대량 작업을 만들려던 시도는 10초당 5회 제한 앞에서 죽었습니다.

그래서 핫픽스를 냈습니다. 길찾기 연동을 지우고, Java로 하버사인 직선거리를 계산해 그걸 보여주는 것으로요. 정보로는 후퇴지만, 한계비용은 0입니다. 매출 이전 단계에서는 옳은 트레이드이고, 이걸 *의식적으로* 하는 것이 설계 리뷰에서 제가 방어할 수 있는 기술이라고 생각합니다.

## 청구서가 그리는 서사

월별 청구서가 이 이야기의 궤적을 혼자 다 그립니다. 11월 **$98**(콘솔 수동 + RDS), dev 환경을 수동으로 늘리며 1월 피크 **$236**, 그리고 Terraform 이관과 RDS→EC2 전환을 끝낸 달부터 **~$150** 고정. 저 월 $86의 절벽이 최적화 그 자체입니다. 장부에 그대로 보입니다.

다만, 그 $150이 진짜 몸집이 아니었습니다. 진짜는 $125였습니다.

## 그 대가로 치른 것

절약에는 값이 있었습니다. 대부분은 그때도 알고 치른 값입니다:

- **데이터 계층 전체가 단일 AZ.** EBS는 AZ에 묶이고, 멀티 AZ는 데이터 계층 비용을 두 배로 만듭니다. prod ECS가 두 AZ에 걸쳐 있던 건 사실상 장식이었습니다. a존이 죽으면 전부 죽는 구조였으니까.
- **백업 보존 기간이 '달'이 아니라 '일' 단위.** WAL 3일, 덤프 60일, dev는 사실상 휘발성.

그리고 몰랐던 값이 하나 있었습니다. **월 $25어치가 좀비 인프라였습니다.** 마이그레이션 후에 분명히 지웠다고 생각한 구 RDS가 연결 0인 채로 여섯 달을 더 돌았고, 그 옆에는 손으로 만들었던 구 VPC 전체와, 이름이 문자 그대로 `temp`인 정체불명 인스턴스가 있었습니다. 이 글을 쓰려고 비용 감사를 하다가 발견했습니다. 그 무렵엔 크레딧이 들어와 있었습니다. 크레딧은 훌륭하지만, 동시에 마취제입니다. **청구서에 $0이 찍히는 순간, 청구서를 읽지 않게 됩니다.**

제일 좋아하는 디테일: 그 로테이션 Lambda는 아무도 쓰지 않는 서비스의 dev 비밀번호를 *지금도* 24시간마다 성실하게 돌리고 있습니다. 자동화는 만든 사람의 의도보다 오래 살아남더군요.

## 에필로그

Muroom은 소프트 런칭을 넘지 못했습니다. 실사용자 8명, 나머지는 지인 테스트. 크레딧이 바닥나는 이번 달, 인프라를 내립니다. 통상의 스타트업 지표로는 실패입니다.

하지만 저는 관리형 서비스가 대신 해주는 모든 일의 동작 모델을 손에 넣고 나왔습니다. 하나하나 직접 다시 만들면서, 어떤 보증에 돈을 낼 가치가 있는지를 한 줄씩 결정해야 했으니까요. 다음에 누가 "RDS냐 자체 운영이냐"를 물으면, 제 대답은 의견이 아니라 숫자로 시작합니다.
